# Google 协议与实测边界

## 样机与范围

2026-10-31：Chromecast Remote，VID/PID 18D1:9450，DIS A0，固件 26.7，macOS 15.8.2 / Apple Silicon。下述结果来自这一台样机，不代表全部固件或第三方兼容款。公开记录不含设备地址、BLE UUID、序列号、音频或原始抓包。

## 语音

ATVV 服务 UUID：`AB5E0001-5A21-4F05-BC7D-AF01F617B664`。TX/RX/CTL 分别为 AB5E0002/0003/0004。样机 TX 仅支持无响应写入。

- 能力请求：`0A 01 00 00 03 03`。
- CTL `0B` 返回版本、编码与帧长；样机帧长 160 字节。
- CTL `08` 请求开麦，需回应 `0C 00`。
- CTL `04` / `00` 驱动语音按下与结束。
- RX 为连续 IMA ADPCM 流，16 kHz，Google 样机高 nibble 在前。
- CTL `0A` 的 predictor / step index 同步在帧边界应用。

人声已通过 BlackHole 链路确认；长语音保活、跨固件音质及每个外部输入法的文字交付不在本次全量验收范围内。

## 普通按键

描述符：report ID 1、两个 8 位 Consumer 数组索引，完整 IOHID 报告应为 `[1, slot0, slot1]`。

本机对照：

| 实际操作 | ATT value，不含 report ID | 常规 IOHID |
| --- | --- | --- |
| 上键按下 | `03` | 未到达 |
| 上键释放 | `00` | 未到达 |
| 返回按下 | `0B` | 未到达 |
| 返回释放 | `00` | 未到达 |
| 上＋返回 | `03 0B` | 收到 `01 03 0B` |

上键和返回各独立重复三次，结果一致。之后对全部实体键登记，14/14 均收到按下及释放；末态为空，无遗留按住。实时解码验证也收到上、返回各三次的完整 12 个边沿。

根因证据支持“设备发送了短报告，但现有 IOHID 路径不转交它们”。它不精确定位本机闭源蓝牙栈内部的某一个函数，也不代表所有系统均如此。

## 为什么使用按需 HCI 接收

管理员权限本身不足够；PacketLogger 曾明确返回 `Bluetooth Profile Required`。临时官方描述文件可验证捕获。此后验证了按会话临时设置 HCI 调试键，无需描述文件或重启，并在退出后恢复旧值。

助手验证 Apple 工具的身份和签名，在 root 私有目录复制完整工具包、校验快照后执行。标准输出只在内存中过滤，不写入原始全机抓包。匹配当前 BLE UUID、连接 handle、设备名称及已验证的输入 characteristic 后，才输出结构化按键集合。

本机已验证输入 attribute 为 `0x0046`。当前公开版本仍使用这个经实测的值；新型号、重新配对或特征布局改变时应复验，不能直接把上游常量当成新设备事实。

接收期间对唯一目标设备独占 HID，避免合规双键的系统原生动作与映射重复。遥控器在系统中是键盘类 HID，内核只允许 root 独占，因此由已获管理员授权的采集助手在会话期间持有独占，并通过 `seize` 记录上报独占设备数；助手退出时内核自动释放。连接身份变化、多个同款设备、权限不完整或助手未能独占时暂停映射。缺失松开保护上限为八秒，因此不承诺无限持续按住。

## 不应误认的服务

`D343BFC0…BFC5` 对应的公开厂商协议为 IR over BLE 家族；BFC5 不能直接当作普通 HID 输入。仅凭订阅它没有消息，不能证明所有普通按键都被系统屏蔽。

## 自动验证

`sh scripts/run-tests.sh` 无需管理员权限。管理员集成测试另见 `scripts/test_capture_helper.py`，覆盖正常停止恢复、拒绝未签名工具、父进程结束恢复。不得在未获授权的机器上自动运行该测试；不要上传原始 pklg 或个人音频来复现问题。

## 连续长按与自动接收补充验收（2026-10-31）

AUDIO_START携带实际stream ID，应用每5秒发送MIC_EXTEND `[0x0E, streamID]`，停止/断线/退出取消。一次持续物理按住实测收到4726个音频通知，首末音频跨度95.07秒，约49.7包/秒，发送19次保活；Handy数据库只新增一条结果（没有公开其内容）。用户确认一直按着时自动停止，日志显示蓝牙断开而非收到正常AUDIO_STOP；因此不把95秒宣称为保证时长或可控软件上限，也不宣称3分钟通过。用户随后确认约1分35秒已满足当前用途。

应用启动后，在目标设备、唯一HID、握手、权限和Apple工具就绪时，已实测自动开启普通按键接收，不需要手动点击开关。管理员授权仍受系统控制；拒绝/手动停止后当次运行不循环启动。
